## What this is

This isn't a library. It isn't a framework. It's a **workbench** — every data structure I've
implemented from scratch, every algorithm I've traced by hand, and every LeetCode problem that
made me close the laptop and walk around the room for ten minutes.

Nothing here is abstracted away. No `Collections.sort()` where a merge sort should be. The point
was never to use the tool — it was to build the tool, break it, and build it again.

```
   2022  ──●  first commit. patterns, loops, a number-guessing game.
   2023  ──●  quiet year.
   2024  ──●●●●●●  391 commits. arrays → strings → recursion → OOP → stacks → queues.
   2025  ──●●●●  242 commits. trees, tries, heaps, graphs, dynamic programming.
   2026  ──●●  segment trees, hard LeetCode, C++ & OS internals.
```

## ▶️ Running anything here

Every file is self-contained. No build system, no dependencies, no `pom.xml`. That's on purpose.

**Java** — 292 of the 308 files ship their own `main()`:

```bash
cd programs_DSA
javac Dijktra_Algorithm.java && java Dijktra_Algorithm
```

**C++**:

```bash
g++ -std=c++17 "C++/N_Queen.cpp" -o nqueen && ./nqueen
```

**C** (the threading ones need pthreads):

```bash
gcc programs_DSA/threads.c -o threads -lpthread && ./threads
```

> **Heads up:** ~16 files are LeetCode submissions (`class Solution`, no `main`) — things like
> [`Max_Sum_Path_Binary_Tree`](programs_DSA/Max_Sum_Path_Binary_Tree.java) and
> [`LC-78(Subsets)`](programs_DSA/LC-78%28Subsets%29.java). Paste them into the judge, or wrap
> them in your own driver.

## 🧭 Why it looks like this

A few things you'll notice, and the reasoning behind them:

- **Duplicate-ish names** (`pallindrome` / `palindrome_string`, `DP_part_1` / `DP_Part3`,
  `Stack_using_2Queue` / `Stack_using_2_Queue`) — these are genuine second attempts, usually
  months apart. I kept both. The diff between them *is* the learning.
- **`trial.java`, `trial_.java`, `trial___.java`** — scratchpads. Every repo has them; most people
  delete them before pushing.
- **No tests.** These are studies, not software. Correctness was verified against judges and by
  hand-tracing.
- **Inconsistent style across years.** 2022-me and 2026-me format code differently. Normalizing it
  would erase the timeline.
